## ✅ Demo Slice 2 (ประเมินมือ) — ฝั่งกรรมการให้คะแนนกดได้แล้ว

ทดสอบผ่านเบราว์เซอร์อัตโนมัติ เขียวติดกัน 3 รอบบน develop `68deb89` (Dwight)

| ขั้น | สิ่งที่ทำ | API | หน้าเว็บ |
|---|---|---|---|
| 1 | กรรมการเห็นคิวงานของตัวเองที่ `/review` | ✅ | ✅ |
| 2 | เปิดงาน ดูคลิป ให้เกรดทุกเกณฑ์ (มีบันทึกร่างในเครื่อง ปิดหน้าแล้วเปิดใหม่ยังอยู่) | ✅ | ✅ |
| 3 | กด **ส่งและล็อก** → ยืนยัน → ส่งแล้วแก้ไม่ได้ งานหายจากคิว | ✅ | ✅ |
| 4 | กรรมการคนสุดท้ายส่งแล้ว ระบบรวมคะแนนให้อัตโนมัติ (score + ช่วงล่าง–บน) | ✅ | ⏳ |
| 5 | คณะกรรมการดูรายการและรายละเอียดผลการประเมิน (`/committee/assessments`) แล้วอนุมัติ | ⏳ | ⏳ |

**ลองกดเอง** (ทำ "เตรียมเครื่อง" ด้านล่างก่อน · ถ้าเคย seed ไว้แล้ว ให้ดึงโค้ดใหม่ → `pnpm db:deploy` → `pnpm db:seed` (ข้อมูลเดิมไม่หาย) → เปิด API ใหม่):
1. เข้าสู่ระบบเป็น `reviewer1@blulens.local` (รหัสผ่าน: ดูในไฟล์ `.env`) → ไปที่ http://localhost:3100/review
2. กด **เริ่ม** ที่งานหนึ่งรายการ → ดูคลิป → เลือกเกรดให้ครบทุกเกณฑ์
3. กด **ส่งและล็อก** → **ยืนยัน** → งานหายจากคิว
4. ลองซ้ำด้วย `reviewer2` / `reviewer3`: งานแต่ละชิ้นต้องมีกรรมการครบ 2 คน ระบบจึงจะคำนวณผล

**ที่ยังไม่มี:**
- หน้าผลการประเมินของคณะกรรมการ (รายการ + รายละเอียด + อนุมัติ) รอ API ฝั่งหลังบ้าน (Kevin กำลังทำ) · ตอนนี้ผลถูกคำนวณและเก็บไว้แล้ว แต่ยังไม่มีหน้าให้ดู (ดูหน้าตาที่ภาพจำลอง `/demo/assessment-result`)
- ขอความเห็นที่สอง · ชุดคลิปมาตรฐาน
- คลิปในข้อมูลตัวอย่างเป็นไฟล์ทดสอบ ไม่ใช่การเล่นจริง
- ออกแบบให้กรรมการไม่เห็นคะแนนของกรรมการคนอื่น เพื่อให้ประเมินอย่างอิสระ

## ลองกดเองทีละขั้น

**เตรียมเครื่อง (ครั้งแรกครั้งเดียว)** ในโฟลเดอร์ `D:\_work\SourceDev\_code\blulens`:
1. คัดลอก `.env.example` เป็น `.env` (ถ้ายังไม่มี) แล้วตั้ง `SEED_DEMO=1`
   - ถ้ามี `.env` อยู่แล้ว: แก้บรรทัด `DATABASE_URL` ให้ชื่อฐานข้อมูลเป็น `blulens_demo` (ฐานใหม่ที่สะอาด ไม่มีข้อมูลทดสอบ) แล้วทำข้อ 3–4 ใหม่
2. `pnpm install`
3. `pnpm db:deploy` (สร้างฐาน `blulens_demo` ให้เองถ้ายังไม่มี)
4. `pnpm db:seed` (รันซ้ำได้ ไม่สร้างข้อมูลซ้ำ)
5. `pnpm dev` แล้วรอให้ขึ้นครบ

**เส้นทางที่กด** (รหัสผ่านทุกบัญชี: ดูในไฟล์ `.env`):
1. เปิด http://localhost:3100/login → ล็อกอินเป็น **แอดมิน** (อีเมลตาม `SEED_ADMIN_EMAIL` ใน `.env`)
2. ไปที่ `/events/new` → ทำ wizard สร้างรายการแข่ง + ประเภท (เช่น คู่ผสม) → กด **เปิดรับสมัคร**
3. ไปที่ `/admin/events/<รหัสประเภท>/entries/new` → เลือกผู้เล่น 2 คน (เช่น member1 + member6) + เลือกทีมแบบพิมพ์แล้วเลือก (ลองพิมพ์ "บลู" จะเจอ Blue Wing) → บันทึก → กด **ส่งต่อให้คณะกรรมการ**
4. ออกจากระบบ → ล็อกอินเป็น `committee@blulens.local` → ไปที่ `/committee/events/<รหัสประเภท>/entries` → **อนุมัติ** หรือ **ปฏิเสธ** (ปฏิเสธต้องใส่เหตุผลอย่างน้อย 10 ตัวอักษร)
5. ออกจากระบบ → ล็อกอินเป็น `member1@blulens.local` → ไปที่ `/events/<รหัสประเภท>/entries` → เห็นรายชื่อคู่ที่อนุมัติแล้ว

**ข้อมูลตัวอย่างที่มีให้:** แอดมิน (มีสิทธิ์คณะกรรมการด้วย), `committee@blulens.local`, `member1` ถึง `member6@blulens.local` (มีเกรดตัวอย่างแล้ว), กรรมการให้คะแนน `reviewer1` ถึง `reviewer3@blulens.local` (มีงานประเมินรอให้คะแนน · คลิปเป็นไฟล์ตัวอย่าง ไม่ใช่การเล่นจริง · หน้าให้คะแนนจะประกาศว่า "กดได้" หลังทดสอบผ่าน) · ถ้าเคย seed ไว้ก่อนแล้ว ให้ดึงโค้ดใหม่ รัน `pnpm db:deploy` และ `pnpm db:seed` อีกครั้ง (ข้อมูลเดิมไม่หาย) แล้วเปิด API ใหม่ · ทีม Blue Wing (บลูวิง), Red Phoenix, Green Valley

**ตัวอย่างหน้าผลประเมินมือ (ภาพจำลอง ยังไม่ใช่ข้อมูลจริง):** http://localhost:3100/demo/assessment-result · ภาพหน้าจอใน `docs/design/mock/` (`assessment-result.png`, `assessment-result-mobile.png`)

**ข้อจำกัดที่รู้แล้ว:**
- ล็อกอินครั้งแรกหลังเปิดเครื่องใหม่อาจต้องกดซ้ำอีกครั้ง
- หน้ารายการแข่ง `/events` แสดงแค่หน้าแรก (ยังไม่มีปุ่มหน้าถัดไป)
- รายการปรับหน้าตาจากการรีวิวของ Pam อยู่ในคิว (bl-26)

## ฐานรากที่เสร็จแล้ว (มองไม่เห็นบนหน้าจอ แต่ต้องมีก่อน)

- โครงฐานข้อมูลครบทุกตาราง (6 บทบาท, ทีม, การประเมิน + โหมดกรรมการน้อย + ชุดคลิปมาตรฐาน, รายการแข่ง, สาย, รอบแบ่งกลุ่ม, ผลแมตช์ 2 ขั้น)
- สูตรสถิติที่ผ่านการทดสอบ: ตรวจคะแนนโดด, Cohen's Kappa, Fleiss' Kappa, บันไดเกรด (score/lower/upper), สถิติชุดคลิปมาตรฐาน
- ตัวจับสายครบ (seed, bye, กันทีมเดียวกันเจอรอบแรก, ถอนตัว)
- สเปกทั้งหมดได้รับอนุมัติจากเจ้าของแล้ว (สถาปัตยกรรม, การประเมิน, จับสาย, รูปแบบการแข่ง)
