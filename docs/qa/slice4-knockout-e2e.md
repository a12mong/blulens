# Gate: รอบน็อกเอาต์ (slice 4, bl-33)

ไฟล์ทดสอบ: `apps/web/e2e/slice4-knockout.spec.ts` · ผลการแข่งขัน (รอบกลุ่มและน็อกเอาต์) บันทึกผ่าน API (umpire1 รายงาน, Committee อนุมัติ); การล็อกกลุ่ม, การจัดสายน็อกเอาต์ และหน้า public ทดสอบผ่าน UI; ไม่ใช้ SQL · น็อกเอาต์ใช้ bo3_21 (ตัวอย่าง 21-10, 21-12)

## Flow หลัก: 6 คู่, 2 กลุ่ม (3+3), ผ่านเข้ารอบกลุ่มละ 2 → 4 ทีม
| ขั้น | ตรวจ | ผลที่คาด |
|---|---|---|
| K1 | ตั้งค่า + เผยแพร่กลุ่ม; preview น็อกเอาต์ก่อนล็อกกลุ่ม | 409 `GROUP_STAGE_NOT_CONFIRMED` |
| K2 | รายงาน+อนุมัติครบทุกแมตช์กลุ่ม; ก่อนล็อกไม่มี `knockout-draw-panel`; ล็อกผ่านปุ่ม UI | หลัง `groupconfirm-done` แผงน็อกเอาต์ปรากฏ |
| K3 | "จัดสายน็อกเอาต์" → สรุป 4 ทีม / 2 รอบ / 2 คู่; สุ่มใหม่ต้องมีเหตุผล ≥5 ตัวอักษร → ฉบับที่ 2; เผยแพร่ | 201/201/200, `knockout-published`; มี 2 รอบรองฯ, 1 นัดชิง, 1 นัดชิงที่ 3 |
| K5 | bracket หลังเผยแพร่ | provisional=false, size 4, thirdPlace มี, champion ว่าง; preview ใหม่ → 409 `DRAW_ALREADY_LOCKED` |
| K6 | รอบรองฯ | ผลที่เพิ่งรายงาน (ยังไม่ยืนยัน) ไม่เลื่อนผู้ชนะ; ยืนยันแล้ว ผู้ชนะเข้านัดชิง, ผู้แพ้เข้านัดชิงที่ 3 |
| K7 | ชิง + ชิงที่ 3 ยืนยัน | champion = ผู้ชนะนัดชิง; thirdPlace.winner ถูกต้อง; รายงานซ้ำนัดที่ยืนยันแล้ว → 409 |
| K8 | หน้า public (Guest) แท็บ "สายน็อคเอาท์" | การ์ดรอบรองฯ+ชิง มีเครื่องหมาย "ชนะ" 3 จุด และคะแนนเกม |
| K8b | **ปัญหาที่พบ (`test.fail`)** | นัดชิงที่ 3 ไม่แสดงบนหน้า public (API ส่ง `thirdPlace` แต่ UI วาดเฉพาะ `rounds`) |

## Flow บาย: 7 คู่, กลุ่ม 4+3, ผ่าน 2 + best third 1 → 5 ทีม (API เท่านั้น)
B1: preview มี size 8 และ 3 บาย; เผยแพร่แล้วรอบแรกมี 4 แมตช์ (3 บาย), bracket 3 รอบ, ผู้ชนะบายอยู่รอบสองแล้ว

## ข้อสังเกตที่ไม่ได้ gate
- หน้า public เปิดแท็บ "รอบกลุ่ม" เป็นค่าเริ่มต้นแม้เผยแพร่น็อกเอาต์แล้ว; ยังไม่มีการแสดงแชมป์ (champion) บนหน้า
- หน้าจัดสายน็อกเอาต์เก็บ preview ไว้ใน state: หลังรีโหลดต้องกด preview ใหม่ (ต้องมีเหตุผล) ก่อนเผยแพร่
- ยังไม่ครอบคลุม: เสมอ/ถอนตัวในน็อกเอาต์, walkover, ผู้เข้ารอบเท่ากันที่ต้องจับสลาก
