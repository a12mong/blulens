## 1. สรุปใน 1 นาที

1. แต่ละประเภท (event) เลือกรูปแบบได้ 2 แบบ: **น็อคเอาท์อย่างเดียว** (ตาม draw.md) หรือ **แบ่งกลุ่ม + น็อคเอาท์**
2. แบ่งกลุ่ม: กลุ่มละ **4 entry** (ปรับได้) จับกลุ่มด้วย seed จากเกรดและ **แยกคนทีม/สโมสรเดียวกันไปคนละกลุ่ม** ให้มากที่สุด แล้วพบกันหมดในกลุ่ม (round robin)
3. ตารางคะแนนกลุ่ม: **ชนะ 3 · เสมอ 1 · แพ้ 0** (ตั้งค่าได้) ตัดสินคะแนนเท่ากันด้วย ผลต่างแต้ม → ผลการเจอกัน → แต้มที่ทำได้ → จับฉลากด้วย seed
4. เข้ารอบ: **N อันดับแรกของทุกกลุ่ม** (ผู้จัดตั้งต่อประเภท) **+ อันดับ 3 ที่ดีที่สุด** ตามโควตา (ไม่บังคับ) → สร้างสายน็อคเอาท์ด้วยตัวจับสายของ draw.md
5. รูปแบบแมตช์ตั้งต่อประเภทและต่อรอบ เช่น รอบกลุ่ม **2 เกม เกมละ 15 แต้ม ไม่มีดิวส์ เสมอ 1–1 ได้** · หรือ **เกมเดียว 30 แต้ม** นับแพ้ชนะ + ผลต่างแต้ม · รอบน็อคเอาท์ **2 ใน 3 เกม 21 แต้ม ดิวส์ถึง 30**

> **คำศัพท์:** ในเอกสารนี้ "**entry**" = ผู้สมัคร 1 หน่วยในประเภทนั้น (เดี่ยว 1 คน / คู่ 2 คน — ที่ bbfriendlymatch และคำของเจ้าของเรียกว่า "ทีม") ส่วน "**ทีม/สโมสร**" = สังกัดใน `teams` ที่ใช้กับกฎแยกคนทีมเดียวกัน

## 2. รูปแบบของประเภท (event format)

| ค่าตั้ง | ตัวเลือก | ค่าเริ่มต้น |
|---|---|---|
| `type` | `knockout` · `groups_knockout` | `groups_knockout` เมื่อ entry ≥ 6, ไม่งั้น `knockout` (decision F1) |

| `advancePerGroup` | 1–2 (ไม่เกิน groupSize − 1) | 2 |
| `bestThirds` | 0 – (จำนวนกลุ่ม − 1) | 0 (ผู้จัดเปิดเองต่อประเภท เช่น bbfriendlymatch ใช้ 2 ในมือ RK/BG และ 0 ในมือ S) |
| `groupMatchFormat` | ดู §5 | 2 เกม × 15 แต้ม ไม่มีดิวส์ เสมอได้ |
| `knockoutMatchFormat` | ดู §5 | 2 ใน 3 เกม × 21 แต้ม ดิวส์ ถึง 30 |

## 3. การจับกลุ่ม (ขยายจาก draw.md — ใช้ seed, PRNG, audit, preview/publish ชุดเดียวกัน)

### 3.1 จำนวนและขนาดกลุ่ม
- จำนวนกลุ่ม `g = floor(N / groupSize + 0.5)` (อย่างน้อย 1) · ขนาดกลุ่มต่างกันได้ไม่เกิน 1 และทุกกลุ่มต้องมี 3–5 entry — ถ้าไม่ได้ ระบบให้ Committee เลือก g เอง
- ตัวอย่าง: N = 12 → 3 กลุ่ม × 4 · N = 10 → 3 กลุ่ม (4, 3, 3) · N = 9 → 2 กลุ่ม (5, 4) · N = 6 → 2 กลุ่ม × 3

### 3.2 การวางลงกลุ่มแบบโถ (pot)
| ขั้น | กติกา |
|---|---|
| เรียง | เรียง entry ตาม `seedScore` (เหมือน draw.md §3, คะแนนเท่ากันตัดสินด้วย PRNG) |
| โถ | โถ 1 = g อันดับแรก · โถ 2 = g อันดับถัดไป · … (โถสุดท้ายอาจไม่เต็ม) |
| วาง | โถ 1: อันดับ 1 → กลุ่ม A, อันดับ 2 → กลุ่ม B … (มือวางกระจายคนละกลุ่มแน่นอน) · โถ 2 เป็นต้นไป: สุ่มกลุ่มด้วย PRNG กลุ่มละ 1 คนต่อโถ |
| กฎทีม | **คนทีม/สโมสรเดียวกันอยู่คนละกลุ่ม** (ใช้นิยาม "ทีมเดียวกัน" ของ draw.md D7) — ตัวแก้เงื่อนไขแบบย้อนรอยเดียวกับ draw.md §4 |
| เลี่ยงไม่ได้ | (ทีมเดียวมี entry มากกว่าจำนวนกลุ่ม) → ใช้แบบที่ชนน้อยที่สุด + Committee กดยอมรับ (ตาม D3) และ **จัดแมตช์ระหว่างคนทีมเดียวกันไว้รอบสุดท้ายของกลุ่ม** (ตรงเจตนา "ไม่เจอกันตั้งแต่แรก") |

### 3.3 ตารางแข่งในกลุ่ม (round robin)
- ทุก entry พบกันหมด 1 ครั้ง · ใช้วิธีวงกลม (circle method) · กลุ่ม 4 คน = 3 รอบ รอบละ 2 แมตช์
- ลำดับในกลุ่ม 4 (ตามลำดับ seed ในกลุ่ม 1–4): รอบ 1 **1v4, 2v3** · รอบ 2 **1v3, 4v2** · รอบ 3 **1v2, 3v4** → มือวางในกลุ่มเจอกันรอบสุดท้าย · กลุ่ม 3/5 คนมี bye หมุนเวียน
- การจัดสนาม/เวลาไม่อยู่ในขอบเขตนี้ (Committee จัดเอง — ดูคำถามเปิด §9)

## 4. ตารางคะแนนกลุ่ม

### 4.1 คะแนนสะสม
| ผลแมตช์ | คะแนน (ค่าเริ่มต้น) |
|---|---|
| ชนะ | 3 |
| เสมอ (เฉพาะรูปแบบที่เสมอได้ เช่น 1–1 เกม) | 1 |
| แพ้ | 0 |
| ชนะบาย/วอล์กโอเวอร์ | ดู F11 |

### 4.2 ลำดับตัดสินเมื่อคะแนนเท่ากัน (ค่าเริ่มต้นตาม bbfriendlymatch)
1. **คะแนนสะสม**
2. **ผลต่างแต้ม** (แต้มได้ − แต้มเสีย ทุกเกมในกลุ่ม)
3. **ผลการเจอกันเอง** — ถ้าเสมอกัน 2 คน: ใครชนะในแมตช์ระหว่างกัน · ถ้าเสมอ 3 คนขึ้นไป: คิดตารางย่อยเฉพาะแมตช์ระหว่างคนที่เสมอ (คะแนน → ผลต่างแต้ม) — แก้ปัญหาที่ bbfriendlymatch เทียบทีละคู่ซึ่งอาจวนกันไม่จบ
4. **แต้มที่ทำได้รวม**
5. **จับฉลากด้วย PRNG + seed ของการจับกลุ่ม** (บันทึกใน audit) — แทนการเรียงตามรหัสทีมของ bbfriendlymatch ซึ่งไม่ยุติธรรมกับรหัสที่ขึ้นต้นด้วยตัวอักษรท้าย ๆ

### 4.3 อันดับ 3 ที่ดีที่สุด (เมื่อ `bestThirds` > 0)
- นำอันดับ 3 ของทุกกลุ่มมาเรียงด้วยเกณฑ์ข้อ 4.2 ข้อ 1, 2, 4, 5 (ข้อ 3 ใช้ไม่ได้เพราะไม่เคยเจอกัน)
- ถ้ากลุ่มมีขนาดไม่เท่ากัน: **ตัดผลที่เจอกับอันดับสุดท้ายของกลุ่มที่ใหญ่กว่าออก** ก่อนเทียบ เพื่อให้ทุกคนเทียบด้วยจำนวนแมตช์เท่ากัน (decision F7)
- อันดับ 3 ที่ไม่ได้โควตาแสดงสถานะ "ลุ้นอันดับ 3" ระหว่างแข่ง แบบ bbfriendlymatch

### 4.4 การปิดรอบกลุ่ม
- ตารางคะแนนคำนวณสดจากผลแมตช์ (ฟังก์ชัน pure ใน `packages/shared`) — ไม่พิมพ์อันดับด้วยมือ
- เมื่อแมตช์กลุ่มจบครบ Committee กด **"ยืนยันผลรอบกลุ่ม"** → ระบบเก็บ snapshot ตารางคะแนนลง `group_standings` (หลักฐานที่ใช้จัดสาย) → ปลดล็อกการสร้างสายน็อคเอาท์
- ก่อนยืนยัน หน้าสาธารณะแสดงสายน็อคเอาท์เป็นช่องว่าง "แชมป์กลุ่ม A" ฯลฯ ไม่แสดงชื่อสมมติ (บทเรียนจาก `knockoutVisibility` ของ bbfriendlymatch)

## 5. รูปแบบแมตช์ (match format) — ตั้งแยกรอบกลุ่ม/รอบน็อคเอาท์

| ค่าตั้ง | ความหมาย | ตัวอย่าง |
|---|---|---|
| `mode` | `fixed_games` (เล่นครบทุกเกม เสมอได้) · `best_of` (ชนะก่อนครึ่งหนึ่ง) | `fixed_games` |
| `games` | จำนวนเกม (`fixed_games`) หรือ N ของ "N เกมชนะก่อน" (`best_of`: 1, 3, 5) | 2 |
| `pointsPerGame` | แต้มที่ชนะเกม | 15 |
| `deuce` | true = ต้องนำ 2 แต้มเมื่อถึง P−1 เท่ากัน | false |
| `cap` | เพดานแต้มเมื่อดิวส์ (เช่น 30 → 29:29 ใครได้ 30 ชนะ) | — |
| `drawAllowed` | ผลรวมเกมเท่ากันนับเป็นเสมอ (`fixed_games` จำนวนคู่เท่านั้น) | true |

**รูปแบบสำเร็จรูป (preset) ที่เสนอ:**

| preset | mode | เกม | แต้ม | ดิวส์/เพดาน | เสมอ | การนับผล |
|---|---|---|---|---|---|---|
| `group_2x15` (ค่าเริ่มต้นรอบกลุ่ม — bbfriendlymatch) | fixed_games | 2 | 15 | ไม่มี (14:14 → ใครได้ 15 ชนะ) | ได้ (1–1) | ชนะ 2–0 = 3 · 1–1 = 1/1 · แพ้ = 0 |
| `single_30` (ตัวอย่างของเจ้าของ) | best_of | 1 | 30 | ไม่มี | ไม่ได้ | ชนะ/แพ้ + ผลต่างแต้มเข้าตาราง |
| `bo3_21` (ค่าเริ่มต้นรอบน็อคเอาท์ — มาตรฐาน BWF) | best_of | 3 | 21 | ดิวส์ ถึง 30 | ไม่ได้ | ชนะ 2 เกมก่อน |
| `single_21` | best_of | 1 | 21 | ดิวส์ ถึง 30 | ไม่ได้ | — |

**ตรวจผลที่กรอก (validation):**
- แต่ละเกม: ผู้ชนะต้องได้ `pointsPerGame` พอดี และอีกฝ่ายน้อยกว่า — ถ้า `deuce`: ผู้ชนะนำ ≥ 2 แต้ม หรือได้ `cap` พอดีเมื่อ `cap − 1 : cap − 1`
- `fixed_games`: ต้องกรอกครบทุกเกม · `best_of`: หยุดเมื่อมีผู้ชนะครบ และห้ามกรอกเกมเกิน
- รอบน็อคเอาท์ไม่มีเสมอเสมอ (ห้ามใช้ `fixed_games` จำนวนเกมคู่)
- ผู้กรอกผล: **กรรมการสนาม (Umpire)** หรือ Committee — ดู §5.1

### 5.1 ผลแมตช์ 2 ขั้น: กรรมการสนามรายงาน → Committee ยืนยัน (F12 ตามที่เจ้าของอนุมัติ)

| สถานะแมตช์ | ใครทำ | ไปสถานะ |
|---|---|---|
| `scheduled` | Umpire ที่ได้รับมอบหมายกรอกผล (ตรวจตาม §5) | `reported` (รอยืนยัน) |
| `reported` | Umpire คนเดิมแก้ได้จนกว่าจะยืนยัน | `reported` |
| `reported` | Committee **ยืนยัน** | `confirmed` |
| `reported` | Committee **ตีกลับ** พร้อมเหตุผล | `scheduled` (Umpire กรอกใหม่) |
| `scheduled` | Committee กรอกเอง | `confirmed` ทันที (ลง audit ว่าข้ามขั้นรายงาน) |
| `confirmed` | Committee แก้ผล (ต้องมีเหตุผล) — ทำได้จนกว่ารอบกลุ่มถูกยืนยัน (§4.4) หรือแมตช์รอบถัดไปของผู้ชนะยังไม่เริ่ม | `confirmed` (เวอร์ชันใหม่ ลง audit) |

- **นับเฉพาะผล `confirmed`** ในตารางคะแนนและการเลื่อนรอบน็อคเอาท์ · หน้าสาธารณะแสดงผล `reported` พร้อมป้าย "รอยืนยัน"
- ยืนยันผลรอบกลุ่ม (§4.4) ได้เมื่อทุกแมตช์ในกลุ่มเป็น `confirmed`/`void`
- การมอบหมาย: Committee มอบหมาย Umpire ต่อรายการแข่ง (เลือกสนามได้ เช่น "สนาม 1–2") และ/หรือระบุ Umpire รายแมตช์ · Umpire กรอกได้เฉพาะแมตช์ที่มอบหมายให้ตัวเองหรืออยู่ในสนามของตัวเอง
- ห้าม Umpire กรอกผลแมตช์ที่ตัวเองเป็นผู้เล่น · ถ้า Umpire มีทีมร่วมกับผู้เล่นในแมตช์ → กรอกได้แต่ติดธง `UMPIRE_TEAM_CONFLICT` ให้ Committee เห็นตอนยืนยัน (ข้อสันนิษฐาน — สนามเล็กมักใช้คนในสโมสร)
- ทุกการรายงาน/แก้/ยืนยัน/ตีกลับ ลง audit (ใคร, เมื่อไร, ค่าก่อน/หลัง, เหตุผล)

## 6. สายน็อคเอาท์หลังรอบกลุ่ม

- ผู้เข้ารอบ `Q = g × advancePerGroup + bestThirds` · ขนาดสาย S = กำลังสองที่ ≥ Q · bye = S − Q ให้มือวางอันดับต้นก่อน (draw.md §3)
- **การจัดลำดับ seed แบบแยกชั้น (ข้อเสนอ — decision F8):** แชมป์กลุ่มทุกกลุ่มเรียงกันเองด้วยเกณฑ์ §4.3 → seed 1..g · รองแชมป์ → seed ถัดไป · อันดับ 3 ที่ได้โควตา → ท้ายสุด
- วางลงสายด้วยลำดับช่องมาตรฐานของ draw.md ภาคผนวก ก + ตัวแก้เงื่อนไขของ draw.md §4 โดยเพิ่ม **"มาจากกลุ่มเดียวกัน" เป็นเงื่อนไขชนอีกข้อ** → รอบแรกของน็อคเอาท์ไม่เจอคนกลุ่มเดียวกันซ้ำ และไม่เจอคนทีม/สโมสรเดียวกัน (เป้าหมายทั้งสองอย่างบังคับแบบเดียวกับ D3: เลี่ยงไม่ได้ → น้อยสุด + Committee ยอมรับ)
- แชมป์กลุ่ม (seed 1..g) จะเจอรองแชมป์/อันดับ 3 จากกลุ่มอื่นในรอบแรก โดยธรรมชาติของลำดับช่อง
- ชิงที่ 3: ถ้า `thirdPlacePlayoff = true` ผู้แพ้รอบรองชนะเลิศแข่งกันอีก 1 แมตช์ (bbfriendlymatch ทำแบบนี้)
- เผยแพร่/สุ่มใหม่/ล็อก ใช้กติกา draw.md §6–7 (D5, D8) ทุกข้อ

ตัวเลือกที่ bbfriendlymatch ใช้จริง คือ **เรียงรวม**: นำทุกคนที่เข้ารอบมาเรียงด้วยเกณฑ์เดียวกันโดยไม่สนว่ามาจากอันดับไหน (รองแชมป์ที่คะแนนดีอาจได้ seed สูงกว่าแชมป์กลุ่มอื่น) — Jim เสนอแบบแยกชั้นเพราะ (1) การเป็นแชมป์กลุ่มต้องได้เปรียบชัดเจน (2) แบบเรียงรวมมีโอกาสให้คนกลุ่มเดียวกันเจอกันซ้ำในรอบแรก ถ้าไม่เพิ่มเงื่อนไขกลุ่ม

## 7. โครงข้อมูลและ API ที่เพิ่ม

### 7.1 ตาราง (Kevin ใส่ใน bl-07 ถ้าอนุมัติ)
| ตาราง/คอลัมน์ | เนื้อหา |
|---|---|
| `events.format` (jsonb) | ค่าตั้งทั้งหมดใน §2 + match format ทั้งสองรอบ + `lockedAt` |
| `groups` | `id`, `event_id`, `draw_id` (ผลการจับกลุ่มเป็น draw ชนิด `group`), `label` (A, B, …) |
| `group_members` | `group_id`, `entry_id`, `seed_in_group` (1..n), `pot` |
| `matches` (ขยาย) | + `stage` (`group`/`knockout`/`third_place`), `group_id?`, `round`, `court?`, `umpire_id?`, `games` (jsonb `[{a, b}]`), `result` (`a_win`/`b_win`/`draw`/`walkover_a`/`walkover_b`/`void`), `status` (`scheduled`/`bye`/`reported`/`confirmed`/`walkover`/`void`), `reported_by/at`, `confirmed_by/at`, `flags` |
| `event_umpires` | `event_id`, `user_id`, `courts` (text[] — ว่าง = ทุกสนาม) |
| `draws` (ขยาย) | + `kind` (`group` / `knockout`) · knockout หลังกลุ่มเก็บ `source_standings_snapshot_id` |
| `group_standings` | snapshot ตอนยืนยันผลรอบกลุ่ม: `group_id`, `entry_id`, `rank`, `played`, `won`, `drawn`, `lost`, `points`, `points_for`, `points_against`, `diff`, `tiebreak_note`, `qualification` (`qualified`/`best_third`/`out`) |

### 7.2 API (เพิ่มใน `docs/api/openapi.yaml` แท็ก `format` — ติดป้าย bl-17 draft)
| Endpoint | ใคร | หน้าที่ |
|---|---|---|
| `PUT /events/{eventId}/format` | Committee | ตั้งค่ารูปแบบ (ก่อนล็อก) |
| `POST /events/{eventId}/groups/preview` | Committee | สุ่มจับกลุ่ม (ได้ `Draw` kind `group`) — publish/verify ใช้ endpoint ของ draws เดิม |
| `GET /events/{eventId}/groups` | ทุกคน | กลุ่ม + สมาชิก + ตารางแข่ง |
| `GET /events/{eventId}/standings` | ทุกคน | ตารางคะแนนสด (หรือ snapshot หลังยืนยัน) |
| `PUT /matches/{matchId}/result` | Umpire / Committee | กรอก/แก้ผล (ตรวจตาม §5) — Umpire → `reported`, Committee → `confirmed` |
| `POST /matches/{matchId}/result/approve` · `/reject` | Committee | ยืนยัน / ตีกลับ (เหตุผล) |
| `PUT /events/{eventId}/umpires` · `GET` | Committee | มอบหมายกรรมการสนาม + สนาม |
| `PATCH /matches/{matchId}/assignment` | Committee | ระบุสนาม/Umpire รายแมตช์ |
| `GET /umpire/matches` | Umpire | แมตช์ที่ตัวเองกรอกได้ |
| `POST /events/{eventId}/groups/confirm` | Committee | ยืนยันผลรอบกลุ่ม → snapshot |
| `POST /events/{eventId}/knockout/preview` | Committee | สร้างสายน็อคเอาท์จาก snapshot (ได้ `Draw` kind `knockout`) |

## 9. ข้อสันนิษฐานและคำถามเปิด

ข้อสันนิษฐาน:
1. กลุ่มใช้กับทั้งประเภทเดี่ยวและคู่ · 1 ประเภท = 1 ชุดกลุ่ม (ไม่มีกลุ่มรอบสอง)
2. ไม่มีระบบจัดสนาม/เวลาอัตโนมัติในเฟสนี้ (bbfriendlymatch ใช้ตารางที่ผู้จัดพิมพ์เอง)
3. ผลแมตช์กรอกโดยกรรมการสนาม (Umpire) แล้ว Committee ยืนยัน (F12 ตามเจ้าของ)

คำถามเปิด:
1. ต้องการระบบจัดคิวสนาม/เวลา (court scheduling) และหน้าแมตช์สดแบบ bbfriendlymatch หรือไม่ — ถ้าต้องการเป็นสเปกแยก
2. ~~role ผู้ตัดสินหน้าสนาม~~ → เจ้าของตอบแล้ว: เพิ่ม Umpire (F12, §5.1)
